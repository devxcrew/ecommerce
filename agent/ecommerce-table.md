# Ecommerce Data Tables

This document describes the Ecommerce tables implemented in CXShop. It is a reference for the current migration-defined schema. It does not create tables, migrations, APIs, or user interfaces.

Source reviewed: E:\Workspace\codexsun\cxshop.

## Scope and conventions

CXShop is an npm monorepo with Platform, Core, Billing, Mail, and Ecommerce API and web apps, plus shared Framework and UI packages. Ecommerce backend modules live in apps/ecommerce/api/src/modules and pair with frontend modules in apps/ecommerce/web/src/modules.

The Ecommerce API uses Kysely with MariaDB/MySQL. Each module owns its migration file. The database composition and migration order live in apps/ecommerce/api/src/database/ecommerce-database.ts. The storefront module composes read data and indexes; it does not own a separate storefront table.

| Owner | Meaning |
| --- | --- |
| Core | Shared product and brand masters. Ecommerce references these records. |
| Ecommerce | Tables created by Ecommerce-owned module migrations. |
| Source cache | Local records that keep Frappe/iShop data and sync state. |

The current database resolver uses DB_MASTER_NAME and ignores its optional database-name argument. These Ecommerce tables have no tenant_id field. This document reflects migration definitions. It does not verify a live database.

## Scope boundary

The Ecommerce migrations do not define customer, cart, order, payment, shipment, or stock-ledger tables. The frontend has a browser cart, but the migrations do not persist it. Core owns product and brand master data. Ecommerce owns storefront details, catalog caches, synchronization, and storefront content.
